Conceptos importantes de React

- **Componentes** (`App`) → Un componente es una pieza de la interfaz de usuario que podemos crear, reutilizar y combinar con otros componentes.

- [**JSX**](03.%20jsx.md) → una sintaxis que permite escribir algo parecido a HTML dentro de JavaScript.

- **State** (`useState`) → datos que pueden cambiar y que hacen que React vuelva a renderizar el componente (actualizar la interfaz).

- **Hooks** (`useEffect`, `useContext`, etc.) → son funciones especiales de React que permiten utilizar características de React dentro de los componentes funcionales.

- [**Props**](05.%20props.md) (properties) → Son el mecanismo mediante el cual un componente padre (`App`) pasa datos o funciones a un componente hijo (`Message`). El flujo de datos es **Unidireccional** de `padre → hijo`, y las props que recibe el hijo son de solo lectura.

- **Eventos** → responder a clics, formularios, etc.

- **Renderizado y listas** → mostrar datos dinámicamente.

## 1. Idea general

El componente `App` tiene:

- `State` → datos que pueden cambiar y que hacen que React vuelva a renderizar el componente.

 - `Effect` → código que React ejecuta como consecuencia de que el componente se monta o cambia.

- `Props` → datos que un componente padre (`App`) le pasa a un componente hijo (`Message`).

```

               App
                │
    ┌───────────┼────────────┐
    │           │            │
  state       effect       props
    │           │            │
advice/count  getAdvice   count
                            │
                            ▼
                          Message

```

## 2. State: `useState`

Tiene dos estados:

``` javascript

const [advice, setAdvice] = useState(''); # Estado 1
const [count, setCount] = useState(0); # Estado 2

```

- Cada uno son como **una variable especial de React**.

### 2.1 `advice`

``` javascript

const [advice, setAdvice] = useState('');

```
Aquí:

- `advice` → valor actual.

- `setAdvice` → función para modificarlo.

- `''` → valor inicial.

Inicialmente:

- `advice` = `''`

Cuando hacemos:

``` javascript

setAdvice(data.slip.advice);

```

- React cambia el estado.

### Ejemplo:

    advice = ""
        ↓
    setAdvice("Never give up")
        ↓
    advice = "Never give up"
        ↓
    React vuelve a renderizar

Y por eso esto:

``` javascript

<h1>{advice}</h1>

```

termina mostrando:

    Never give up

### 2.2 `count`

Lo mismo ocurre aquí:

``` javascript

const [count, setCount] = useState(0);

```

Inicialmente:

``` javascript

count = 0

```

Y cada vez que llamamos a:

``` javascript

setCount((c) => c + 1);

```

- Se aumenta el contador.

```

0
↓
1
↓
2
↓
3

```

### ¿Por qué no hacemos esto?

Podríamos pensar:

``` javascript

let count = 0;

```

y después:

``` javascript

count++;

```

Pero eso no le dice a **React** que debe volver a renderizar el componente.

En cambio:

``` javascript

setCount((c) => c + 1);

```

le dice a React:

- Quiero actualizar este estado y, como consecuencia, React debe volver a renderizar el componente.

**Nota**:

- Ese es uno de los conceptos más importantes de React.

## 3. Effect: `useEffect`

Ahora tenemos:

``` javascript

useEffect(function () {
  getAdvice();
}, []);

```

Esto es un **effect**.

Este permite sincronizar un componente con
sistemas externos, como APIs, temporizadores, suscripciones o
servicios externos.

Por ejemplo:

- hacer `fetch`

- suscribirse a eventos

- trabajar con APIs del navegador

- timers

- conectar/desconectar servicios, etc.

Es como decirle a React:

- Cuando `App` se monte, ejecuta `getAdvice()`.

### `[]` es muy importante.

Significa que no tiene dependencias.

Por lo tanto, el effect se ejecuta **después del primer renderizado del componente**.

#### Flujo:

    App se renderiza
        ↓
    React pinta la interfaz
        ↓
    useEffect()
        ↓
    getAdvice()
        ↓
    fetch(...)
        ↓
    setAdvice(...)
    setCount(...)
        ↓
    App vuelve a renderizar

Por eso cuando se abre la aplicación, automáticamente aparece un aviso sin que haya que presionar el botón.

---

## 4. `getAdvice()` es una función normal

Esta parte:

``` javascript

async function getAdvice() {
  const res = await fetch('https://api.adviceslip.com/advice');
  const data = await res.json();

  setAdvice(data.slip.advice);
  setCount((c) => c + 1);
}

```

No es algo exclusivo de React.

Es simplemente una función JavaScript que:

- Hace un `fetch`.

 - Obtiene los datos.

 - Actualiza el estado `advice`.

 - Actualiza el estado `count`.

---

### Lo importante es desde dónde se llama.

Se llama desde **dos** lugares:

### 4.1 Desde el `useEffect`

``` javascript

useEffect(function () {
  getAdvice();
}, []);

```
---

Esto hace que se obtenga un aviso automáticamente al montar `App`.

---

### 4.2 Desde el botón

``` javascript

<button onClick={getAdvice}>Aviso</button>

```
---

Esto hace que se obtenga otro aviso cuando el usuario hace click.

## 5. Props (properties)

Aquí `App` está utilizando otro componente:

``` javascript

<Message count={count} />

```

Y le está pasando un dato:

``` javascript

count={count}

```

Ese dato es una `prop`.

### Ejemplo:

    App
    │
    │ count = 5
    │
    └──────► Message
            │
            │ props.count = 5
            ▼
        "Has leído 5 avisos"

---

**Importante**

Los datos normalmente fluyen:

    PADRE
    ↓
    ↓ props
    ↓
    HIJO

No:

    PADRE
    ↓
    HIJO
    ↑
    └── modifica directamente el estado del padre ❌

Por ejemplo, `Message` no puede hacer esto:

``` javascript

props.count = 10; // ❌

```

Las `props` son de solo lectura para el componente que las recibe.

---

### 5.1 ¿Qué recibe `Message`?

El componente:

``` javascript

function Message(props) {
  return (
    <p>
      Has leído <strong>{props.count}</strong> avisos
    </p>
  );
}

```

Cuando hacemos:

``` javascript

<Message count={count} />

```

React construye un objeto `props` algo así:

``` javascript

{
  count: 5
}

```

Por eso dentro de `Message` se puede acceder a:

``` javascript

props.count

```
Y el resultado:

    5

Entonces React termina generando:

``` HTML

<p>
  Has leído <strong>5</strong> avisos
</p>

```

## 6. Diferencia entre: `State` vs `Props`

### 6.1 State

El state pertenece al componente.

En el caso:

``` javascript

const [count, setCount] = useState(0);

```

`App` tiene ese estado.

Y `App` puede modificarlo con:

``` javascript

setCount(...)

```

### 6.2 `Props`

Las `props` **son datos que un componente recibe de otro componente**.

Aquí:

``` javascript

<Message count={count} />

```

`App` le está diciendo a `Message`:

- Te voy a pasar mi valor `count`.

`Message` lo recibe:

``` javascript

function Message(props) {

```

y lo utiliza:

``` javascript

props.count

```

En otras palabras:

    STATE
    "Los propios datos que pueden cambiar"


    PROPS
    "Datos que le pasa el componente padre"

## 7. Resumen

### 1. Inicio:

``` javascript

count = 0
advice = ''

```

### 2. React renderiza:

    Has leído 0 avisos

### 3. Después se ejecuta:

``` javascript

useEffect(...)

```

### 4. que llama:

``` javascript

getAdvice()

```

La API devuelve un aviso.

Entonces:

``` javascript

setAdvice(...)
setCount(...)

```

cambia el estado.

- React detecta el cambio y vuelve a renderizar.

Ahora:

    advice = "Some advice..."
    count = 1

Y como App vuelve a renderizar:

``` javascript

<Message count={count} />

```

ahora se convierte en:

``` javascript

<Message count={1} />

```

Por lo que Message recibe:

``` javascript

props.count === 1

```

y muestra:

    Has leído 1 avisos

Después hacemos click:

    CLICK
    ↓
    getAdvice()
    ↓
    fetch()
    ↓
    setAdvice()
    ↓
    setCount()
    ↓
    React renderiza nuevamente
    ↓
    <Message count={2} />
    ↓
    Has leído 2 avisos

- **State** = datos que React controla y que pueden cambiar.

- **Props** = datos que un componente padre le pasa a un hijo.

- **Effects** = código que React ejecuta para sincronizar el componente con algo externo o realizar trabajo después del render.

---

              ┌──────────────┐
              │     App      │
              │              │
              │    STATE     │
              │ advice/count │
              └──────┬───────┘
                     │
             actualiza state
                     │
                     ▼
               React renderiza
                     │
            ┌────────┴────────┐
            │                 │
       <h1>{advice}</h1>   <Message />
                              │
                           PROPS
                         count={count}
                              │
                              ▼
                           Message

Y `useEffect` entra en el flujo para hacer cosas como el `fetch`:

    App renderiza
        ↓
    useEffect
        ↓
    fetch API
        ↓
    setAdvice / setCount
        ↓
    nuevo render
        ↓
    nuevas props
        ↓
    Message se actualiza

Lo que este ejemplo muestra:

El patrón fundamental de **React**; un cambio de `state` provoca un nuevo render, y ese nuevo render hace que los valores calculados y las `props` de los componentes hijos se actualicen.
