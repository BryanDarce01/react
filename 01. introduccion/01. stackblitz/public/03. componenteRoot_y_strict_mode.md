``` jsx
import React from 'react';
import ReactDOM from 'react-dom';

function App() {
  return <h1>Hello React!</h1>;
}

const root = ReactDOM.createRoot(
  document.getElementById("root")
);

root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);

```

# 1. ¿Qué hace `createRoot`?

Tenemos:

``` jsx

const root = ReactDOM.createRoot(
  document.getElementById("root")
);

```

## Aquí están pasando dos cosas:

``` jsx

document.getElementById("root")

```

busca en el HTML un elemento como:

``` HTML

<div id="root"></div>

```

- Ese `<div>` es el contenedor donde React va a colocar la aplicación.

Después:

``` jsx

ReactDOM.createRoot(...)

```

le dice a React:

- Quiero que este elemento sea la raíz de la aplicación React.

Y por eso podemos hacer:

``` jsx

root.render(
    <React.StrictMode>
    <App />
    </React.StrictMode>
  );

```

# 2. ¿Qué significa `root.render()`?

``` jsx

root.render(<App />);

```

Significa:

- React, renderiza el componente `App` dentro del elemento `#root`.

Primero:

``` jsx

function App() {
  return <h1>Hello React!</h1>;
}

```

Entonces:

``` jsx

root.render(<App />);

```

terminará produciendo algo parecido a:

``` HTML

<div id="root">
  <h1>Hello React!</h1>
</div>

```

**Importante**: React no está creando otra página HTML. 

Está utilizando ese `<div id="root">` como punto de entrada para manejar la interfaz.

# 3. `StrictMode`

``` jsx

root.render(
  <React.StrictMode>
    <App />
  </React.StrictMode>
);

```

Aquí `StrictMode` es como un modo de revisión para asistirnos mientras desarrollamos.

No es un componente visual. Es decir, el usuario no verá algo como "Strict Mode" en la pantalla.

React utiliza `StrictMode` para detectar ciertos problemas potenciales en el código.

Algo así:

    root
    │
    └── StrictMode
        │
        └── App
                │
                ├── Header
                ├── Main
                └── Footer

`StrictMode` envuelve a `App` y, por lo tanto, aplica sus comprobaciones a `App` y a los componentes que estén debajo.

# 4. ¿Por qué a veces parece que React ejecuta algo dos veces?

Con:

``` jsx

<React.StrictMode>
  <App />
</React.StrictMode>

```

durante el desarrollo, React puede ejecutar ciertas funciones/componentes más de una vez para ayudarnos a encontrar código que tenga efectos secundarios incorrectos.

### Por ejemplo:

``` javascript

function App() {
  console.log("App ejecutándose");

  return <h1>Hello React!</h1>;
}

```

Podría salir:

    App ejecutándose
    App ejecutándose

- Y pensar que React está renderizando dos veces.

No necesariamente significa que la aplicación vaya a mostrar dos App.

Es una comprobación intencional de `StrictMode`.

La idea es detectar problemas como:

``` javascript

function App() {
  // ❌ Algo que no debería ejecutarse simplemente por renderizar
  hacerAlgoImportante();

  return <h1>Hello</h1>;
}

```

React intenta hacer notar este tipo de problemas antes de que lleguen a producción.

# Resumen

1. Busca el elemento HTML `#root`.

2. Crea una raíz de React ahí.

3. Renderiza `App` dentro de esa raíz.

4. Usa `StrictMode` para que React haga comprobaciones adicionales durante el desarrollo.

## `createRoot` ≠ `StrictMode`

- `reateRoot()` → conecta React con el DOM y crea la raíz de React.

- `root.render()` → le dice qué componente renderizar.

- `StrictMode` → activa comprobaciones adicionales para detectar problemas durante el desarrollo.
