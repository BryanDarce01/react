![useState](../img/02_event_and_state/01_state.png)
![Reglas de useState](../img/02_event_and_state/02_guia_del_estado.png)

## 1. `useState` devuelve 2 valores

Cuando hacemos:

``` JSX

const [step, setStep] = useState(1);

```

### `useState(1)` devuelve un arreglo con dos elementos:

    [
    valor actual,
    función para actualizar ese valor
    ]

Por eso usamos destructuring:

``` JSX

const [step, setStep] = useState(1);

```

Equivale conceptualmente a:

``` JSX

const estado = useState(1);

const step = estado[0];
const setStep = estado[1];

```

Así que:

- `step` → contiene el **estado actual**

- `setSte`p → función que permite **actualizar el estado**

- `1` → valor inicial del estado

Por ejemplo:

``` JSX

const [step, setStep] = useState(1);

console.log(step); // 1

```

Y:

``` JSX

setStep(2);

```

le dice a React:

- Quiero que `step` pase a valer `2` y que vuelvas a renderizar este componente.

## 2. ¿Por qué `setStep` es una función?

Porque React necesita que exista una manera controlada de modificar el estado.

No hacemos:

``` JSX

step = 2; // ❌

```

Sino:

``` JSX

setStep(2); // ✅

```

Esto es importante.

Cuando hacemos:

``` JSX

setStep(2);

```

React sabe:

    El estado cambió
        ↓
    Hay que volver a renderizar
        ↓
    El componente se ejecuta nuevamente
        ↓
    step ahora vale 2

## 3. `useState` solamente se puede llamar al inicio del componente

Esta es una regla de los Hooks:

**Los Hooks deben llamarse en el nivel superior del componente.**

Por ejemplo, esto está bien:

``` JSX

function App() {
  const [step, setStep] = useState(1);
  const [isOpen, setIsOpen] = useState(true);

  // ...
}

```

Pero esto está mal:

``` JSX

function App() {
  if (something) {
    const [step, setStep] = useState(1); // ❌
  }
}

```

También:

``` JSX

function App() {
  function algo() {
    const [step, setStep] = useState(1); // ❌
  }
}

```

Y

``` JSX

function App() {
  function algo() {
    const [step, setStep] = useState(1); // ❌
  }
}

```

### ¿Por qué?

Porque React necesita que los Hooks se ejecuten **siempre en el mismo orden en cada render**.

Por ejemplo:

``` JSX

function App() {
  const [step, setStep] = useState(1);
  const [isOpen, setIsOpen] = useState(true);
  const [name, setName] = useState("Pepe");
}

```

React internamente necesita poder asociar:

    Primer useState  → step
    Segundo useState → isOpen
    Tercer useState  → name

Por eso no debemos hacer que un Hook aparezca o desaparezca dependiendo de un `if`.`

# B. Actualizar el estado basándonos en el estado actual

``` javascript

export default function App() { const [step, setStep] = useState(1);

const [isOpen, setIsOpen] = useState(true);

// const [test, setTest] = useState({ name: "Jonas" });

function handlePrevious() { if (step > 1) setStep((s) => s - 1); }

function handleNext() { if (step < 3) { setStep((s) => s + 1); setStep((s) => s + 1); } } 

// BAD PRACTICE

test.name = "Pepe";
setTest({ name: "Pepe" }); }

```

Aquí está esta línea:

``` javascript

setStep((s) => s + 1);

```

Esto es muy importante.

`setStep` puede recibir directamente el nuevo valor:

``` javascript

setStep(2);

```

pero también puede recibir una función:

``` javascript

setStep((s) => s + 1);

```

Cuando le pasamos una función, React le proporciona el **estado anterior/actual**.

Por ejemplo:

``` javascript

step = 1

```

entonces:

``` javascript

setStep((s) => s + 1);

```

hace conceptualmente:

    s = 1

    s + 1 = 2

    step → 2

Si después `step` es 2:

    s = 2
    s + 1 = 3

    step → 3

## 1. ¿Por qué no simplemente `setStep(step + 1)`?

También podemos hacer:

``` javascript

setStep(step + 1);

```

y en muchos casos funcionará perfectamente.

Por ejemplo:

``` javascript

function handleNext() {
  if (step < 3) {
    setStep(step + 1);
  }
}

```

Eso está bien.

Pero cuando el nuevo estado depende del estado anterior, React recomienda la forma funcional:

``` javascript

setStep((s) => s + 1);

```

Porque está expresando explícitamente:

- Dame el valor anterior de step y a ese valor súmale 1.

**Esto se vuelve especialmente importante cuando hacemos varias actualizaciones**.

Por ejemplo:

``` javascript

setStep(step + 1);
setStep(step + 1);

```

Podríamos pensar:

    step = 1

    primero → 2
    segundo → 3

Pero no necesariamente ocurre así, porque ambas expresiones están utilizando el mismo valor de `step` del render actual.

En cambio:

``` javascript

setStep((s) => s + 1);
setStep((s) => s + 1);

```

React puede aplicar las actualizaciones una después de otra:

    step = 1

    primera función:
    s = 1 → 2

    segunda función:
    s = 2 → 3

Por eso la forma funcional es especialmente útil cuando hacemos varias actualizaciones del mismo estado o cuando el nuevo estado depende del anterior.

## 2. Y finalmente, el comentario de `test`

``` javascript

const [test, setTest] = useState({ name: "Jonas" });

```

Y después:

``` javascript

// BAD PRACTICE

test.name = "Pepe";
setTest({ name: "Pepe" }); }

```

**❌ No debemos modificar directamente el objeto del estado**

Esto es incorrecto.:

``` javascript

test.name = "Pepe";

```

Porque estamos modificando directamente el objeto que React tiene como estado.

En su lugar:

``` javascript

setTest({ name: "Pepe" });

```

creamos un nuevo objeto y se lo entregamos a React.

Incluso si el objeto tuviera más propiedades:

``` javascript

const [test, setTest] = useState({
  name: "Jonas",
  age: 30
});

```

no haríamos:

``` javascript

test.name = "Pepe"; // ❌

```

Sino:

``` javascript

setTest({
  ...test,
  name: "Fred"
});

```

El `...test` copia las propiedades existentes y luego sobrescribe `name`.

## Resumen

``` javascript

const [state, setState] = useState(initialValue);

```

Significa:

    state
      ↓
    valor actual

    setState
      ↓
    función para actualizarlo

    initialValue
      ↓
    valor inicial

Y

``` javascript

setState(nuevoValor);

```

cuando ya conocemos el nuevo valor.

Mientras que:

``` javascript

setState((valorAnterior) => nuevoValor);

```

cuando el nuevo valor depende del anterior.

Y la idea central de **State** es:

- State es la memoria del componente. Cuando actualizamos el **state** mediante su función `set...`, React vuelve a renderizar el componente para reflejar ese nuevo estado en la interfaz.
